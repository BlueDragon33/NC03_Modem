# NC03-WP02 — Canonical settings and capability registry

Projection status: **PLANNED**
Blueprint: `project:nc03-modem / 1.0.0 / B4`
Depends on: `NC03-WP01`

> Execution projection only. Canonical authority remains in `.blueprint/*` and `docs/NC03-PROJECT-CONSTITUTION.md`.

## Objective
Create one versioned registry that becomes the authoritative setting/action model for UI, read, write and firmware-profile mapping.

## Preconditions
- Universal Constitution adoption `1.1.0` is valid.
- NC03-WP01 is COMPLETE with evidence.

## Owned scope
- Stable setting/action IDs independent of vendor labels.
- Types, validation, sensitivity and danger class.
- Capability lifecycle UNMAPPED → READ_MAPPED → WRITE_CANDIDATE → WRITE_VERIFIED → HARDWARE_ACCEPTED.
- Readback/recovery policy and UI metadata.

## Non-goals
- No unrelated feature work.
- No endpoint/request/result inference without evidence.
- No PASS from CI alone when hardware/human evidence is required.

## Execution sequence
1. Define the registry schema.
2. Translate every parity item to one canonical ID.
3. Attach firmware mapping as evidence references, not durable identity.
4. Drive UI metadata from registry where practical.
5. Add duplicate-ID and compatibility tests.

## Acceptance gates
- [ ] Every parity row maps exactly once.
- [ ] WRITE_VERIFIED is impossible without required evidence fields.
- [ ] No duplicate setting authority exists in screen code.
- [ ] Registry schema compatibility is tested.

## Required evidence
- Exact revision / PR-head CI.
- Work-package-specific artifacts and regression tests.
- Real-hardware or human evidence whenever this prompt requires it.

## Fail-closed / stop conditions
- A stock control has ambiguous semantics; keep it UNKNOWN rather than guess.

## Anti-patch rules
- No screen-specific modem fetch/write path.
- No duplicate canonical state or duplicate compatibility gate.
- No CSS override used to hide component/layout ownership defects.
- No test weakening or catch-and-ignore to recover green CI.
- If assumptions change, update canonical state before this prompt.

## Handoff
After all gates have evidence, mark `NC03-WP02` COMPLETE and activate only the next dependent Work Package.
